# 逐题讲解与演示

做对一道书题后，棋盘下方会说明“为什么对”；无论对错，作答后都可以点“一步一步看讲解”，在真实棋盘上逐步落子。每一步都配有文字，并在棋盘上标出“气”“眼”“×”等记号。部分题目还附有对比演示，例如“白棋逃不掉”“如果下在别处”“眼：假眼”。这些内容不是视频，而是程序按围棋规则算出的局面事实，语言模型只负责把文字改写得更顺口。

## 谁负责什么

- `cloud/explain.mjs`：按规则计算。逐手说明提子、打吃、长气、连接、送吃，以及罩住出路、分成两只眼、破眼的斜角、死子被关在里面等情况。题目所属的类型由章节决定（判断、做眼、破眼、做活、吃子、对杀、选子）。
  - 眼形看斜角：中间的眼最多让对方占 1 个斜角，边和角上的眼一个都不能让。
  - 局部做眼和破眼用小范围搜索，双方都可以停一手。
  - 吃子用逐步加深的读秒：先浅后深，避免一开始就搜深线，把预算耗在旁支上，反而漏掉简单的征子。
- 判断题只在读出的结论与书上已核对的答案一致时，才写“所以是……”和对应演示；不一致时只陈述事实，绝不和答案唱反调。“判断活棋死棋”和“白棋能否成眼”在读不出一致结论时不出讲解。
- `scripts/explanation-model.mjs`：先由规则拼出一段“为什么对”（关键一手做了什么，加上最后的结果）。再让 MiniMax M3.1-Flash 改写成适合小朋友读的话。改写后的文字要逐项核对，否则退回规则原文：
  - 数字、黑白编号和围棋术语都必须出自原文；
  - 原文里的编号一个都不能少，“提掉”“真眼”“活”等结论词也不能丢；
  - 不能把提子、打吃安到另一手棋上；
  - 不能出现繁体字、英文字母或坐标。

## 生成与存储

讲解里含有答案，所以和书题一样只存在 D1 的 `lesson_explanations` 表中（迁移 `0004`），不放进公开的静态资源。Worker 只在“落子、提交答案、提交选子、看讲解”这几个动作时，读取当前这道题的讲解。

```bash
npx wrangler d1 migrations apply go-coach-wnam --remote   # 首次建表
node scripts/build_explanations.mjs --export --apply      # 导出书题 → 计算 → 改写 → 写入并读回比对
```

- 模型地址默认是本机 magpie（`--endpoint`、`--model` 可以改），用 `--no-model` 则只用规则原文。
- 改写结果缓存在 `.local/explanations/model-cache.json`，原文不变时不重复调用模型。
- `--apply` 写入后会整表读回，比对摘要。
- 讲解的格式变了要升 `EXPLAIN_VERSION`，Worker 只读取当前版本。

## 和学习记录的关系

- 没做对或还没独立做对时，看讲解和以前“看参考解法”一样，记为“提示后作答”。
- 独立做对后回头看讲解属于复习，不计入求助，也不会让这题回到复习队列。
- 演示只改变当前显示的棋盘，点“返回原局面”后恢复。

## 已知限制

- 做活类题目只数出分开的眼，不做完整死活证明。胀死牛、扩大眼位、占据要点等章节，多数只有逐手说明，没有结论句。
- 连接、分断、老鼠偷油、大头鬼等题目，结论多停留在“只剩几口气”，读不出“逃不掉”时不写。
- 讲解的事实是按书上的第一条正解算出来的。如果孩子走的是另一条能提掉目标的路线，标题会写成“书上正解的思路”。
